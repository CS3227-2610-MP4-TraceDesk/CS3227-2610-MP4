What I will do differently

Change

Stop giving a fixed reading list by default. Left free, the agent read 17–28 files, not all 98 linked docs.

Add

Ask agents to read in batches and run tests once. Steps cost tokens, files mostly don’t.

Keep

A blind, read-only checker for work with a detailed spec.

Add

Tests for the two problems the checker found, so the tests catch them next time.

So what did I learn about context? I expected the short list to give cheaper code. It didn't. It was only a bit cheaper when the spec covered everything, it missed a rule once, and in job 3 it cost more. When the agent could choose, it did not read everything. It read between 17 and 28 files per job, not the 98 documents that are linked from my rules. What really drove the token count was the number of steps, because each step sends the whole conversation again. So I'll stop giving a fixed list by default, and instead ask agents to read in batches and avoid running the tests over and over. I'll keep the blind checker for spec-heavy work, and add tests for the two problems it found. The feature code I kept passes all 55 tests.
