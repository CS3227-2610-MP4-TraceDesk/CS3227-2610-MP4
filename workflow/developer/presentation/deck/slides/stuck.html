Each step sends the whole conversation again. All three passed the same tests. The rerun still cost 40% more than B, because it carried the whole list in every step.

Job 3 surprised me, because the focused agent used almost twice as many tokens as the broad one. The reason is the number of steps. Every time an agent runs a command, the whole conversation so far is sent to the model again, so more steps means more tokens. A read its files one at a time, which took 40 steps. To check if that was the cause, I reran A with the same list but told it to read everything in one go. It dropped to 12 steps and 1.13 million tokens, so the reading pattern explains about half the gap. It was still 40 percent more than B, because it loaded the whole list at the start and carried it in every step, even the parts this job did not need.
