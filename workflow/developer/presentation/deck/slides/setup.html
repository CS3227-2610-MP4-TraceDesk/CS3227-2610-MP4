Here's how I ran it. I used Claude Code to design the tests and launch the runs, and Codex wrote all the feature code. First, the tests. I turned the spec into 55 test cases before any code existed. The agents could see 41 of them. I kept 14 in a folder outside the repository, to check whether the code follows the spec and not just the tests it can see. Then I split the feature into three small jobs. For each job, two Codex agents started from the same commit, at the same time, each in its own git worktree so they could not see each other's work. Agent A was only allowed to read seven set documents plus the job's own files. Agent B could read anything. Their prompts were the same except for that one line. Finally, a third agent that could not edit anything reviewed both versions, labelled X and Y, so it did not know which was which. Everything ran from the Codex command line, which reports exact token counts.
