The 14 hidden tests

Job 1 · Reply

  • Same key twice → reject
  • 300 emoji count as 300, not 600
  • Control characters → reject
  • Broken emoji half → reject
  • Spaces and accents kept exactly

Job 2 · What is sent

  • Fields in spec order, not request order
  • Notes with same time sorted by id
  • Instruction under 1500 bytes
  • 8000-byte limit counts bytes, not letters
  • Edited note detected as out of date

Job 3 · Permissions

  • Wrong developer refused before notes are read
  • “Not allowed” beats “AI is off”
  • Reassigned mid-request → not sent
  • Second check re-reads the database

Kept in a folder outside the repo. Copied in only after a writer finished. Every version passed all 14.

Source: dev-ai-test-cases.md (cases V07 V11 V15 V17 V21, C02 C05 C09 C12 C13, A05 A11 A14 A16).

These are the 14 tests the agents never saw. They check the small rules in the spec that are easy to miss, like counting emoji correctly, or refusing the wrong developer before reading any notes. I kept them in a folder outside the repository, and only copied them in after an agent had finished, then removed them again. I also searched every agent's command log afterwards, and none of them looked in that folder. In the end every version passed all 14, so the hidden tests did not separate A and B. The one bug that did, in job 1, was something none of my tests checked.
