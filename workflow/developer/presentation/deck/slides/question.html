Two questions

Context · Lecture 9

If the agent reads less, is the code worse or just cheaper?

Checker · Lecture 8

Does a reviewer agent find enough to pay for itself?

I judged both by results: tests passed, bugs found, time taken. Not by how many tokens were used.

The first question is about context. My project rules tell the agent to read only what is relevant. Before, I measured that the files DEV-AI needs are about 14 times smaller than everything linked from the rules. But a smaller set only helps if the code is still correct. The second question is about the checker, which is the generator and verifier idea from Lecture 8. A reviewer agent costs tokens, so I wanted to see if it finds anything the tests miss. For both, I looked at results, not just token counts, because Lecture 9 says token counts alone don't tell you if it was worth it.
