Two questions

Context · Lecture 9

If the agent reads less, is the code worse or just cheaper?

Checker · Lecture 8

Does a reviewer agent find enough to pay for itself?

I judged both by results: tests passed, bugs found, time taken. Not by how many tokens were used.

I had two questions. The first is about context. Our project rules tell the agent to read only what is relevant. If you follow every link in those rules you get 98 documents, and the files this feature actually needs are about 14 times smaller. So a short list saves a lot of reading, but only if the code is still correct. That's the context engineering idea from Lecture 9. The second question is about a checker, the generator and verifier idea from Lecture 8. A reviewer agent costs tokens, so does it find anything the tests miss? For both, I judged by results, meaning tests passed and bugs found, not just token counts, because a cheap run that gives wrong code isn't a saving.
