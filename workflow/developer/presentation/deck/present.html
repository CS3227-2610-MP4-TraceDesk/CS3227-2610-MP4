The feature: AI suggestions for the developer

TraceDesk is a bug tracker. When a developer is working on a bug, they can ask the AI for possible causes and next steps. The AI only gives advice. It cannot change the bug report.

The 14 hidden tests

Job 1 · Reply

  • Same key twice → reject
  • 300 emoji count as 300, not 600
  • Control characters → reject
  • Broken emoji half → reject
  • Spaces and accents kept exactly

Job 2 · What is sent

  • Fields in spec order, not request order
  • Notes with same time sorted by id
  • Instruction under 1500 bytes
  • 8000-byte limit counts bytes, not letters
  • Edited note detected as out of date

Job 3 · Permissions

  • Wrong developer refused before notes are read
  • “Not allowed” beats “AI is off”
  • Reassigned mid-request → not sent
  • Second check re-reads the database

Kept in a folder outside the repo. Copied in only after a writer finished. Every version passed all 14.

Source: dev-ai-test-cases.md (cases V07 V11 V15 V17 V21, C02 C05 C09 C12 C13, A05 A11 A14 A16).

How careful to be with these results

Only 3 pairs, run once each

Another run could come out differently. This is what I saw, not a rule.

I picked A’s file list

The rule A missed sat in the wrong doc. With better docs, A might have got job 1 right.

The checker is the same model

It may share the writers’ blind spots. I checked every finding by hand.

Times are rough

A and B ran together on my laptop and shared its CPU. Token counts are not affected.

What I will do differently

Change

Stop giving a fixed reading list by default. Left free, the agent read 17–28 files, not all 98 linked docs.

Add

Ask agents to read in batches and run tests once. Steps cost tokens, files mostly don’t.

Keep

A blind, read-only checker for work with a detailed spec.

Add

Tests for the two problems the checker found, so the tests catch them next time.
